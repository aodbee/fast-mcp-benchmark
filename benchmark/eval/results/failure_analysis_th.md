# การวิเคราะห์สาเหตุความผิดพลาดของระบบเปรียบเทียบบนฐานข้อมูล 800,000 แถว

## 1. ขอบเขตและวิธีการ

การวิเคราะห์ใช้เฉพาะไฟล์ผลลัพธ์ (`llm_results.jsonl`, ระเบียนสุดท้ายต่อคู่ system–qid) โดยไม่เรียก LLM ใหม่ ครอบคลุม 60 คำถามในขอบเขต (delayed_projects 31, department_summary 21, staff_advances 8) ต่อ 8 ระบบ คำตอบที่ผิดทั้งหมดถูกประมวลผล SQL ซ้ำบนฐานข้อมูลแบบอ่านอย่างเดียว (เพดาน 20 วินาที) แล้วจัดเข้าหนึ่งในหมวดสาเหตุ และอ่าน SQL เพื่อวินิจฉัยสาเหตุเชิงความหมาย เกณฑ์ตัดสินทำซ้ำตาม `ex_match` ใน `run_llm.py` (ค่าเผื่อ 0.011, ไม่คำนึงลำดับคอลัมน์)

## 5. หลักฐานด้านปัญหาการให้คะแนนและความเป็นธรรมของการทดลอง

1. **ความกำกวมของคำว่า "delayed"** คำถามและ glossary ไม่ได้นิยามคำนี้ แต่ gold และคำอธิบายเครื่องมือ Fast-MCP ("remaining unspent budget exceeds threshold") นิยามเป็น remaining > threshold เท่านั้น ส่วนตัวอย่าง (DEMOS) ของ DAIL/Vanna เผยนิยามเดียวกัน ระบบที่ไม่มีทั้งสองแหล่งจึงเดาเอง การอ่านว่า "ล่าช้า = มีกิจกรรมที่ยังไม่เสร็จ" เป็นการตีความที่สมเหตุสมผลตามคอลัมน์ `is_completed` ดังนั้นคำตอบผิด 26 รายการนี้ควรรายงานเป็น "model error ภายใต้ข้อกำหนดที่กำกวม" มิใช่ความผิดพลาดล้วน ๆ นี่คือหลักฐานเดียวที่ชี้ว่าคำตอบที่ถูกปฏิเสธอาจยอมรับได้ตามถ้อยคำของคำถาม
2. **คำถามที่ gold ว่าง** 5 จาก 60 รายการ (q012, q023, q031, q036, q050) มี gold เป็นเซตว่าง และอีก 7 รายการมีเพียง 1 แถว คำถามที่ gold ว่างผ่านได้ด้วย query ใดก็ตามที่ได้ผลว่าง จึงไม่มีอำนาจจำแนก (8.3% ของข้อสอบ)
3. **ตัวให้คะแนนผ่อนปรน** `ex_match` จับคู่ค่าของ gold กับคอลัมน์ใดก็ได้ในแถวที่สร้าง จึงไม่ตรวจชื่อ/ตำแหน่งคอลัมน์ (สลับ net กับ used ก็ผ่านได้) ในคำตอบผิดที่ตรวจไม่พบผลลบเท็จจากค่าเผื่อ 0.011 หรือการตัดที่ LIMIT (ความเสมอ)
4. **ReAct** ใช้ 8 ขั้น และ observation เพียง 5 แถว 49 จาก 52 รายการจบด้วยเพดานขั้น ผลต่ำ (8/60) จึงสะท้อนการออกแบบเอเจนต์บางส่วน ไม่ใช่ความสามารถของแนวทางโดยตรง

## 6. ความเสี่ยงการรั่วไหล/ทางลัดของ DAIL และ Vanna

| ระบบ | คำตอบถูก | SQL เหมือน DEMO หลังแทนพารามิเตอร์ (ตรงกันทุกตัวอักษรหลัง normalize) | ความคล้าย ≥ 0.90 |
|---|---|---|---|
| dail_sql_style | 60 | 60 (100%) | 60 (100%) |
| vanna_style | 60 | 43 (71.7%) | 60 (100%) |

SQL ที่ถูกต้องทั้งหมดเป็นแม่แบบของ DEMO ที่แทนค่าแผนก/เดือน/เกณฑ์ (Vanna ส่วนที่เหลือต่างเพียงชื่อ alias และรูปแบบ ความคล้ายต่ำสุด 0.959) DEMOS มีแม่แบบครบทั้งสามชนิดคำถามและเท่ากับ SQL ของ gold ดังนั้นความแม่นยำ 100% ของสองระบบนี้วัดความสามารถในการคัดลอกแม่แบบ ไม่ใช่การสร้าง SQL อย่างอิสระ นอกจากนี้คำถามสองข้อในไฟล์ (q086, q103) เหมือนคำถามใน DEMOS ทุกตัวอักษร แม้ไม่อยู่ในชุด 60 ที่ประเมิน และ 36/60 คำถามใช้รหัสแผนกเดียวกับ DEMO (มีเพียง 20 แผนก)

## 7. ข้อสรุป

ความผิดพลาดของระบบ SQL แบบ zero-shot ถูกครอบงำโดยปัจจัยเดียว คือการตีความ "delayed" ต่างจากข้อกำหนด gold (26 รายการ) ไม่ใช่ข้อผิดพลาดด้านชนิดข้อมูลหรือเส้นทาง join; ReAct ล้มเหลวเชิงโครงสร้างของเอเจนต์; ส่วน DAIL, Vanna และ Fast-MCP ถูกทุกข้อ แต่ DAIL/Vanna ได้เปรียบจากการรั่วของแม่แบบ และ Fast-MCP ได้นิยาม "delayed" จากคำอธิบายเครื่องมือ จึงควรรายงานผลควบคู่การทดสอบความไวต่อนิยาม (เช่น เพิ่มนิยาม "delayed" ใน glossary) และใช้ชุดคำถามที่ไม่มีแม่แบบซ้ำกับ DEMOS
